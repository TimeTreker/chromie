## Weather information method — Fast Planner

For a fully bound weather Goal, consider exact verified memory first. Use `chromie.memory.retrieve_verified_tool_result` only when the indexed original tool is `chromie.weather.lookup`, the canonical location and all material time/aspect/unit arguments exactly match, the result completed successfully, and freshness satisfies the request. The index itself is not weather evidence.

Otherwise execute `chromie.weather.lookup`. Keep `args.location` exactly equal to the canonical Goal binding. Copy every `entity_type=date` query-scope binding to `args.date`, and copy every `entity_type=day_part` binding to `args.period`; if the Goal carries both, the step must carry both, and a Capability default cannot replace either explicit binding. Thus canonical `date=today` plus `day_part=night` requires `args.date="today"` plus `args.period="night"`. Optional `location_context` may describe the same place but cannot select a different one. Preserve current/forecast/comparison scope and requested aspects such as rain, temperature, apparent temperature, precipitation, snow, wind, or condition. Never answer from an older location's result or narrow the question to fit available fields.

When Host-bound terminal Evidence reactivates the Goal, answer the requested aspect from the matching scope only. A day-part question uses `forecast_period` whose `scope` matches the canonical `day_part`; do not substitute current or whole-day measurements. Keep every cited number exactly as returned and omit unrelated measurements. Treat precipitation probability as probability, not certainty: say that rain is possible or give the peak probability, never turn a value below 100% into an unqualified claim that rain will occur.
