## Weather information method — Fast Planner

For a fully bound weather Goal, consider exact verified memory first. Use `chromie.memory.retrieve_verified_tool_result` only when the indexed original tool is `chromie.weather.lookup`, the canonical location and all material time/aspect/unit arguments exactly match, the result completed successfully, and freshness satisfies the request. The index itself is not weather evidence.

Otherwise execute `chromie.weather.lookup`. Keep `args.location` exactly equal to the canonical Goal binding. Preserve the Goal's human temporal scope and use only the selected Capability's declared `argument_realization` contract to produce provider-local temporal arguments; record those transformed arguments as Planner semantic-realization provenance. Optional `location_context` may describe the same place but cannot select a different one. Preserve current/forecast/comparison scope and requested aspects such as rain, temperature, apparent temperature, precipitation, snow, wind, or condition. Never answer from an older location's result or narrow the question to fit available fields.

When Host-bound terminal Evidence reactivates the Goal, answer the requested aspect from the matching source-grounded human scope only. Use provider period evidence only when the Planner's Capability-bound realization established that period; do not substitute current or whole-day measurements. Keep every cited number exactly as returned and omit unrelated measurements. Treat precipitation probability as probability, not certainty: say that rain is possible or give the peak probability, never turn a value below 100% into an unqualified claim that rain will occur.
