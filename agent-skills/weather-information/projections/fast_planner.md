## Weather information method — Planner

For a fully bound weather Goal, consider exact verified memory first. Use `chromie.memory.retrieve_verified_tool_result` only when the indexed original tool is `chromie.weather.lookup`, the canonical location and all material time/aspect/unit arguments exactly match, the result completed successfully, and freshness satisfies the request. The index itself is not weather evidence.

Otherwise execute `chromie.weather.lookup`: a mismatched location, date/horizon, aspect, unit, completion state, or freshness requires a fresh read, and one Goal may use memory while another uses a fresh lookup without mixing their bindings or evidence. Keep `args.location` exactly equal to the canonical Goal binding. Preserve the Goal's human temporal scope and use only the selected Capability's declared `argument_realization` contract to produce provider-local temporal arguments; record those transformed arguments as Planner semantic-realization provenance. Optional `location_context` may describe the same place but cannot select a different one. Preserve current/forecast/comparison scope and requested aspects such as rain, temperature, apparent temperature, precipitation, snow, wind, or condition. Never answer from an older location's result or narrow the question to fit available fields. Distinguish an unavailable weather Capability, `location_not_found`, a provider/network/timeout failure, and a successful result.

When Host-bound terminal Evidence reactivates the Goal, decide only whether that Evidence answers the requested aspect in the matching source-grounded human scope. Provider period evidence answers it only when the Planner's Capability-bound realization established that period; current or whole-day measurements do not substitute for it. When it answers, establish the answer Need over that Evidence; you author no wording, and Social Cognition words the answer from the cited Evidence.
