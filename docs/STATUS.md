regex motion and pose agents, catalog phrase-action boosts, weather-specific
route repair, conversation follow-up/new-topic phrase classification, static
ontology wording, route-specific Core exception classification, and the legacy
ToolAgent's direct weather Provider path. Session memory now requires a typed
model-authored `MemoryUpdateProposal`. Current model, Plan, task-proposal, API,
trace, scenario, and qualification identities emit canonical
`capability_id`/`capability_ids`; retained legacy artifacts remain readable at
bounded compatibility boundaries. A later live weather trace corrected four
operational gaps without adding semantic Host rules: Agent Skill selection now
has a schema-consistent single-Goal binding and viable repair budget, Fast/Deep
clarification fields are structurally aligned, unresolved external reads cannot
become factual responses, and Chinese place bindings may receive generic Latin
provider-query forms while remaining canonically unchanged. The repository now
reviews every proposed chat turn against available non-chat affordances, keeps
attached social framing subordinate to the substantive responsibility, and
exposes bounded recent terminal Goals for model-authored continuity. A completed
external-result follow-up may use only previously delivered, Host-marked
evidence-bound dialogue; the verified-memory index alone cannot become answer
evidence. Goal Association now sends typed mixed-responsibility and existing-
Goal material-update candidates through one model-owned semantic review. The
Host does not compare phrases or bindings to decide meaning; retained Goal
bindings remain provenance-stable, and the model creates a fully bound
replacement Goal when it judges that the user changed a material entity.
The model-owned continuity review requires a fresh exact read when such a
correction still depends on external facts; it cannot relabel a prior entity's
result as the replacement entity's result.
Goal Association's schema distinguishes unchanged continuation, read-only
reference, and user-supplied clarification. The model still selects the
relationship from meaning; typed Host validation only rejects a state-changing
relationship that carries no description or resolved-gap delta and permits one
model repair. A new location directly named in the current turn must remain a
contiguous verbatim user-language binding; referent-backed indirect locations
retain the model-resolved canonical value plus the supplied referent ID and
indirect surface form. The Host validates that provenance shape and may request
one model repair, but does not extract the place or choose its meaning. A
capability-dependent Goal may become a direct `respond` Plan only when delivered
evidence-bound dialogue names that exact Goal. Capability executor routing
follows declared effects: verified
memory retrieval is a trusted read in the tool lane, while only a declared
`memory_write` enters the model-authored memory-update lane. This classification
does not decide whether the user's meaning calls for prior evidence or a fresh
lookup. Every pending safe-read response in either an `execute` or `mixed` Plan
receives an independent Response Composer model
review without prior result contents, and its typed completion is retained for
qualification. The repository
policy gate protects the authority boundaries. Pinned Ruff/Mypy execution remains
a required local static gate rather than evidence claimed from the restricted
artifact sandbox. See [Final Core-Principle Audit](FINAL_CORE_PRINCIPLE_AUDIT.md).
