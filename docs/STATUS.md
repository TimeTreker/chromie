# Chromie Current Status
Status: current implementation and evidence authority
Chromie remains a development project, but its core voice and simulator-backed
embodied path is implemented and has retained end-to-end evidence; “development”
means ongoing qualification rather than an absent central loop. The maintained
**Goal-driven single semantic authority** keeps ingress/reflex/admission in the Gateway, ordinary meaning and planning in Core, and effect authority in trusted Host/provider boundaries.
## 2026-08-15 Goal/Planner and Social-Attention authority correction (source-only)

The generated-voice daily-life suite exposed reusable semantic boundaries rather than scenario-specific wording. Owner-reviewed design now also closes the broad architecture-discovery phase: Epistemic Qualification and Forward Adaptation remain cross-cutting inputs to existing owners, evidence integrity is distinct from claim sufficiency, retained-evidence immutability is distinct from retention lifetime, and conversational wording ownership is per act rather than universally owned by Response Composer. The architecture conclusions were first consolidated as design/documentation; the current source now implements the first claim-specific Epistemic Qualification and bounded Forward-Adaptation slices described below, while target qualification remains revision-bound and separate. Current source retains the earlier corrections for typed information scope, semantic capability entailment, truthful unavailability, dynamic evidence, and bounded Fast/Deep reconsideration, and now closes two additional authority leaks. Fast Goal Interpretation emits provider-neutral Responsibility proposals plus optional native conversational progress; exact Capability IDs, executable arguments/actions, and provider work belong to Planner after canonical Goal Association. Legacy Fast route/intent remains compatibility/diagnostic evidence only and cannot grant, suppress, or filter Planner Capability access; Planner execution shape is derived from canonical Goal completion metadata. A prospective `fast_speech` acknowledgement may still start early as Goal Progress Communication, but no safe-read/provider request starts before the Goal/Planner boundary. Social Attention is now anchored to semantic primary human-observable Activity meaning rather than to internal cognition milestones, execution modalities, or a once-per-turn interaction-state cooldown. `InteractionResponse` remains only a coordination envelope: speech transport, Vocal modes, body/media requests, Capability IDs, and request IDs are realization evidence and do not become Primary Activities. Responsibility/Goal sits above Activity; one Goal may own several canonical conversational/Plan-step Activities, while a high-level provider can keep a behavior atomic. Activity identity therefore follows semantic Work/Plan granularity rather than Goal count or execution modality. Independent Activities remain independently eligible for optional fail-soft decoration. Speaking, singing, humming, recitation, expressive speech, and nonverbal vocalization remain modes of one personal Vocal Expression.
Agent Skill selection likewise rejects generic external-information methods for local sensor state or persistent mutations. This is a source-change claim only: the 16-scenario live voice suite must be rerun before any semantic qualification improvement is claimed.

## Compatibility state

`POST /interaction` and `POST /run` remain compatibility interfaces. Their old
CapabilityAgent semantic planner is emergency-only and requires explicit service
and per-turn authority gates. Normal Goal-driven apply failures and excluded
lanes do not enter it. Exact Core action proposals may cross a deterministic
compatibility adapter, but the adapter cannot reinterpret meaning or authorize
execution.

The compatibility planner should be removed after current replay, live-service,
and operator rollback evidence shows that no maintained profile depends on it.
